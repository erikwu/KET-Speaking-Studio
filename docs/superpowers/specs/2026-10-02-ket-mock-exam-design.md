# KET Speaking 模拟考设计规格

## 目标

在 KET Speaking 本地跟读页中新增模拟考模式，按 Part 1 / Phase 1、Part 1 / Phase 2、Part 2 的顺序练习已加载的 Markdown 材料。学生对着麦克风作答，应用在本机转写并由本地语言模型按语义评分；学生可以查看参考答案或参考台词，考试结束时查看转写、分项评分和提示次数。

## 已确认的产品规则

- 仅处理当前载入的 Markdown，按材料当前解析顺序出题。
- 录音、转写和评分全部在本机处理，不向云服务上传录音或文本。
- 仅在用户点击录音时请求麦克风权限；停止录音后释放麦克风轨道。
- 临时录音用于当前识别请求，成功或失败后均删除，不保留录音文件。
- 每项回答评估切题度、信息完整度、语法和词汇，每项 0–5 分、合计 0–20 分。不评发音或口音。
- 评分是练习参考，不是官方考试分数；接受含义相同、措辞不同的合理回答。
- Part 1 听问题后作答；参考答案默认隐藏。每次主动展开英文参考答案计一次提示。参考答案可使用现有本机语音朗读。
- Part 2 显示情景描述和当前学生轮次的中文提示。中文提示是题目本身，不计提示。英文参考台词默认隐藏，每次主动展开计一次提示。
- 每场考试内，每个 Part 2 情景随机决定一次开场方，顺序如下：
  - 电脑先开：电脑播放 Speaker A 第一句；学生根据 Speaker B 中文提示回答；电脑播放 Speaker A 第二句；进入下一情景。
  - 学生先开：学生根据 Speaker A 第一句对应的中文提示回答；电脑播放 Speaker B；学生根据 Speaker A 第二句对应的中文提示回答；进入下一情景。
- 每个 Part 2 情景使用本材料的前三条 A/B/A 对话作为轮次与参考文本。
- 识别或评分失败时保留当前题目；转写成功但评分失败时保留转写并允许只重试评分。识别失败后提示重新录音。
- 如果麦克风、语音识别模型、评分模型或其运行环境不可用，清楚说明原因，不阻止普通跟读模式。
- 考试中的答案、分数和提示统计仅保存在当前浏览器页面内存；结束后显示汇总，开始新考试或离开页面即重置。不写入 Markdown、资源包、数据库、localStorage 或日志。

## 方案和边界

沿用 `speech/server.ts` 的本地服务、`speech/app.ts` 的前端状态和当前 `parseMarkdown()` 输出，不增加单独服务或外部 API。增加一个考试界面/状态机和本机考试推理入口：MLX Whisper 负责英文转写，MLX-LM 上的量化 Qwen3 负责结构化语义评分。现有 TTS 继续播放问题、参考答案和电脑对话台词；考试只使用其已加载的 Markdown 台词，不生成考试专用音频。

组件职责：

1. **考试 UI / 状态机（`speech/app.ts`、`speech/index.html`、`speech/styles.css`）**：开始/结束考试、分段与题目导航、录音、答案提示、电脑台词播放、转写与评分呈现、考试内统计。
2. **本机考试 API（`speech/server.ts`）**：模型能力检测、限制请求大小、接收本机录音、管理推理 worker、校验评分结果并返回可读错误。
3. **考试推理 worker（新增 `speech/exam_worker.py`）**：以 JSON Lines 控制协议启动一次常驻本机子进程，按需加载 MLX Whisper 与 MLX-LM 模型，分别执行转写和语义评分；模型加载失败通过标准错误/协议响应报告。
4. **安装与文档（`install.command`、`speech/README.md`、`README.md`）**：准备 `mlx-whisper`、`mlx-lm` 兼容运行依赖，下载并验证两个考试模型，说明新增磁盘占用和无模型模式。

仅 8788 跟读服务承载本功能；8787 图片生成服务不参与考试。

## 模型与本机要求

- 识别：`mlx-community/whisper-large-v3-turbo`，Hugging Face 页面展示量化 MLX 权重约 1.61 GB，使用 `mlx-whisper`。
- 评分：`mlx-community/Qwen3-4B-4bit`，Hugging Face 页面展示 Apache-2.0，MLX 权重约 2.26 GB，使用 `mlx-lm`。
- 识别模型的上游 `openai/whisper` 仓库为 MIT 许可；评分权重页面标注 Apache-2.0。模型下载仍仅发生在显式运行安装脚本时。
- 新增权重约 3.9 GB，实际安装需要额外空间容纳文件系统/缓存和现有环境。安装器必须将其纳入可用磁盘空间估算，并对已下载模型做结构完整性校验。
- 两个模型目录位于仓库根目录 `models/`，具体子目录名分别为 `whisper-large-v3-turbo` 和 `Qwen3-4B-4bit`。不将模型放入资源包或 Git。
- 安装依赖不得破坏现有 `mlx-audio`、图片生成环境；选择兼容版本，并在安装后检查三个 MLX 能力是否可导入。
- 模型能力独立报告。模拟考仅在 ASR、评分模型及其 runtime 全部就绪时启用；模型缺失时普通朗读、已有离线语音和已有情景图片继续可用。

参考页面：

- [mlx-community/whisper-large-v3-turbo](https://huggingface.co/mlx-community/whisper-large-v3-turbo)
- [openai/whisper 上游许可](https://github.com/openai/whisper/blob/main/LICENSE)
- [mlx-community/Qwen3-4B-4bit](https://huggingface.co/mlx-community/Qwen3-4B-4bit)

## 考试资料映射与流程

### 开考校验

开始考试前，页面需要确认当前材料已成功解析、题目结构可支持考试，并且本机 ASR、评分模型、runtime 均可用。材料按以下规则识别：

- Part 1 / Phase 1 和 Part 1 / Phase 2：每组需要一条 Q 和至少一条 A；Q 为题目，第一条 A 为评分参考答案。其它答案变体用于提示选择，按材料次序排列。
- Part 2：每个情景至少需要三条且前三条角色顺序为 A/B/A；第一条 A、B、第二条 A 分别是三轮参考台词，三个轮次各需要对应行非空的 `translation` 作为中文作答提示。
- 不满足上述结构的组不进入考试，开始前显示被跳过的数量；每个分段至少有一道有效题，Part 2 至少有一个有效情景，才能完整开考。若材料缺少任一分段或有效题，明确指出缺失分段并阻止开考，避免考试中途出现空段。
- 出题次序固定为 Phase 1 所有有效组、Phase 2 所有有效组、Part 2 所有有效情景；每组不重新排序。

### Part 1

进入题目后播放 Q 的英文语音，答案保持隐藏；允许重播当前问题。学生点击录音开始/停止；停止后自动转写并评分。转写文本、四项分数、总分和简短反馈出现在当前题下，随后学生可以继续下一题。学生可主动展开第一条英文参考答案及其答案变体；每次从隐藏状态主动展开记一次提示。可使用现有 TTS 按钮试听已展开的参考答案，不计额外提示。

### Part 2

每个情景进入时展示情景描述；随机顺序按本场考试内的情景 ID 保存，因此页面重绘或重试不重新抽签。每轮按该轮中文提示录音、转写和评分。电脑台词使用现有本机 TTS，播放完成后才进入学生下一轮；合成或播放失败保留当前轮次，并提供重试播放或跳过该电脑台词后继续，跳过不影响提示计数。每个情景均可单独展开英文参考脚本；每次从隐藏状态展开记一次提示。Part 2 按 A/B/A 三条台词中的学生轮次映射评分参考：

| 开场方 | 顺序 | 学生答题参考台词 |
| --- | --- | --- |
| 电脑 | 电脑 A1 → 学生 B1 → 电脑 A2 | B1 |
| 学生 | 学生 A1 → 电脑 B1 → 学生 A2 | A1、A2 |

### 录音与设备权限

- 用户显式点击“开始录音”才调用浏览器麦克风 API。开始失败说明浏览器权限或设备问题，并保持题目不变。
- 单条作答最长 120 秒；到时自动停止并处理，用户也可手动停止。录音以浏览器支持的媒体格式采集，转换为 PCM WAV 后经 loopback `127.0.0.1` 发送给本机服务；请求体上限 25 MiB。
- 服务将音频放入系统临时目录或考试专用临时目录，识别结束后在 `finally` 路径删除；也拒绝越限请求并删除临时文件。应用不将原始录音写入常规音频目录、错误日志或资源包。
- UI 显示“录音仅发送至本机 `127.0.0.1` 服务，不上传外网，处理后删除”。麦克风轨道在手动停止、自动停止、取消/离开考试、切换页面和错误后均释放。

## 转写与语义评分

### 转写

- 使用 `mlx-community/whisper-large-v3-turbo` 离线转写，语言提示为 English，返回识别出的英文原文，不做翻译或改写。
- 空白、无语音或不可解码结果视为识别失败；提示重录，当前题不前进、不评分。
- 转写完成后立即在 UI 展示原始识别文本供学生核对。当前版本不提供手工编辑入口，避免无意中把编辑文本当作 ASR 结果；评分失败时可以重试评分。

### 评分

调用 Qwen3 本机评分模型时提供题目、参考答案/参考台词、学生转写、KET A2 学习语境和固定评分准则。提示要求模型忽略用户材料中的命令式文本，把题目与答案视作不可信的学习内容；使用 JSON schema/严格 JSON 输出，服务端验证范围和字段后才返回。

| 维度 | 0 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 切题度 | 未回应题目或意思不相干 | 主要回应题意，存在明显偏题 | 直接、恰当地回应题意 |
| 信息完整度 | 没有可用信息 | 回答主要信息点但漏掉一部分 | 覆盖参考回答的关键意图/信息点 |
| 语法 | 多处错误使含义难以理解 | 有错误但总体可理解 | 语法适合该回答，错误极少或没有 |
| 词汇 | 用词不足以表达意思 | 词汇基本合适但较单一或有误用 | 词汇准确且适合表达内容 |

1、2、4 分分别表示由相邻锚点界定的中间水平。每项结果包括 `score`（整数 0–5）和中文 `feedback`（一句简短、具体的练习建议）；总分由服务端累加，范围 0–20。模型必须依据表达含义评分，不要求逐字匹配参考答案；不评发音、口音、语速或音色。空转写不调用评分，直接作为识别失败处理。

评分接口失败、超时、非法 JSON 或越界分数时，保留成功转写，不显示伪造的分数，并提供“重试评分”。

## API 与状态

- `/api/config` 新增独立的 ASR 模型、ASR runtime、评分模型、评分 runtime 与 `examAvailable` 状态；保留已有返回字段兼容性。
- `POST /api/exam/transcribe` 接收有大小上限的 WAV 二进制请求，返回 `{ transcript }`；服务只临时落盘或以内存方式传递，确保请求完成后清理。
- `POST /api/exam/score` 接收 `{ question, reference, transcript }`，返回各项整数分数、反馈和总分；服务端验证结构、字符串长度和分数范围。
- 两个接口仅监听现有本地服务的 `127.0.0.1`，模型未就绪时返回明确的 503 和缺失能力说明。
- 将新后台推理请求与现有 TTS worker 的管理分开，避免模型输出污染接口 JSON、相互打断常驻进程或占用 TTS 作业队列。worker 未启动时按需启动；模型加载一次后供本场服务复用，应用退出时回收。
- 浏览器考试状态以明确阶段表示：`ready`、`playing-prompt`、`recording`、`transcribing`、`scoring`、`answer-result`、`playing-dialogue`、`summary`、`error`。异步响应须绑定当前考试 ID 与题目 ID；用户切换题目/结束考试后，过期结果不可覆盖当前状态。

## 结果与数据生命周期

- 每个回答展示学生转写、四项分数、总分与练习建议；失败项标注未完成，不伪装为 0 分。
- 结束页按 Part 1 Phase 1、Phase 2、Part 2 展示已评分题数、四维平均分、总分平均值、各题结果和提示次数；分母只包括成功评分回答，并显示各阶段未完成数。
- 提示计数按显式“查看答案/台词”的每次展开动作分别累计，按题目/情景汇总，Part 2 中文提示不计。打开后隐藏再展开会再次计数；重新渲染不会额外计数。
- 这些状态不持久化。结束页显示期间留在内存；开始新考试、关闭/刷新页面、换材料时清空考试数据并停止录音。
- 资源包继续仅包括当前已支持的 Markdown、WAV 和图片，绝不包括模拟考录音、转写、分数、提示统计或考试模型权重。

## 无模型与失败处理

- 8788 服务启动仍不强制要求任一模型安装。普通材料读取和已有离线音频/图片行为维持原样。
- 缺失任一考试模型/runtime 时，模拟考入口说明需要的本机能力并禁用开考；不阻塞其它跟读功能。
- 浏览器无麦克风、用户拒绝权限、设备被占用、格式转换失败时，显示对应处理建议并留在当前题。
- 模型 worker 启动、加载、推理、超时、无效结果错误使用中文说明具体环节。转写失败允许重录；评分失败保留转写并只重试评分；TTS 播放失败提供重播/跳过该台词后继续选项；未完成回答在结束总结中标记为未完成。
- 页面异常关闭时操作系统/浏览器会结束录音流；应用不重启或扫描旧的考试音频临时文件。系统临时目录的文件使用唯一名且处理结束必删。

## 不在范围内

- 在线识别、在线评分、云端日志或账号服务。
- 发音、口音、语速评估，或与 ElevenLabs 的 TTS 音质比较。
- 官方 KET 等级换算、正式考试报告、长期历史、用户账号、导出成绩。
- 手工修改 ASR 结果、跳过指定学生题、重复整套考试、随机乱序题目、跨刷新恢复考试。
- 考试专用语音合成、Part 2 图片重生成、修改既有 Markdown 格式。

## 验收场景

1. 在模型就绪的 Apple Silicon Mac 上按完整顺序开始考试；Phase 1/Phase 2 答题后均显示转写及 4 项评分，Part 2 按所抽开场顺序交替播放/作答，并使用对应 A/B/A 参考文本评分。
2. 对任一题展开参考答案后提示计数加一；隐藏后再次展开再加一；Part 2 中文提示展示不改变提示计数；结束页按阶段显示该统计。
3. 拒绝麦克风、ASR 出错、评分模型返回非法结果或电脑语音播放失败时，当前题和可重试数据按上述失败规则保留，不丢失已得到的转写/分数。
4. 完成或失败的每次转写后，临时录音文件都不存在；开发者工具网络面板只显示 loopback 本地请求，没有第三方服务请求。
5. 任一考试模型不存在时 8788 仍可启动，考试入口禁用并解释原因；现有普通跟读、离线资源导入/播放和已有图片查看保持可用。
6. 资源包导入导出没有考试音频、考试文本、分数、提示次数或模型权重；开始新考试、换材料或刷新页面清空上一场会话。
7. 安装脚本对两个模型均能断点续传并验证所需文件完整性，不重下已完整模型；安装后 `/api/config` 能准确反映每项能力。
